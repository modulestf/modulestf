# Check C: Module Structure

> **Part of:** [terraform-module-reviewer](../SKILL.md)
> **Purpose:** The operative fails-when and severity rules of Check C. Rule numbers refer to the [Mandatory Rules](../SKILL.md#mandatory-rules) in SKILL.md.
> **Engine text:** the fails-when and severity text of the rules the facts engine detects is in [engine/check-c-structure.md](engine/check-c-structure.md). It is part of this check: the full variant reads it with this file, and each moved bullet below points to its section.

**Reads:** the changed `.tf` files, the module file layout, and the `variables.tf` of every local submodule a `module` block in the scope of [Pass-through to a Local Submodule](engine/check-c-structure.md#pass-through-procedure-structurepassthrough-field-drift) calls, judged against [Module Structure Patterns](../../terraform-module-maintainer/references/module-structure.md), [Service Archetypes](../../terraform-module-maintainer/references/service-archetypes.md), and tiers 1, 2, and 5 of the [Coverage Checklist](../../terraform-module-maintainer/references/coverage-checklist.md).

**Provider facts:** four rules here can need a provider page, read per [Rule 2](../SKILL.md#rule-2-provider-schema-from-mcp-never-from-memory) as [Check B](check-b-coverage.md) reads it. `structure.schema-shape-flattened` needs the block and argument names of the provider's structure. `structure.sibling-block-asymmetry` needs them when it compares a dynamic block against the schema rather than its siblings. `structure.sibling-argument-omitted` needs to know whether the resource's own schema carries the routing argument. `structure.docs-contradict-code` needs a page when whether the promised behaviour happens depends on what a resource or data source does with its arguments, for example which of a policy document data source's inputs end up in which of its attributes. When that page is unavailable, the rule does not fire on that case, and its `rule_id` is named in the `review.check-not-run` of [Rule 4](../SKILL.md#rule-4-a-check-that-cannot-run-is-a-finding) with the type and version. A case these rules decide from the module's own code alone still fires.

**Fails when:**
- A resource added by the change ignores conditional creation, so `create = false` no longer produces an empty plan.
- `structure.output-no-try`: moved to [engine/check-c-structure.md](engine/check-c-structure.md#structureoutput-no-try).
- `structure.variable-untyped`, `structure.missing-description`: moved to [engine/check-c-structure.md](engine/check-c-structure.md#structurevariable-untyped) and [engine/check-c-structure.md](engine/check-c-structure.md#structuremissing-description).
- A nested object input flattens or renames the provider's structure instead of matching it.
- A dynamic block added by the change covers fewer fields than its sibling blocks, or than the schema for that block.
- `structure.wrong-file`: moved to [engine/check-c-structure.md](engine/check-c-structure.md#structurewrong-file).
- Tags or labels are not propagated to a resource added by the change that supports them.
- A new `enable_*` boolean defaults to `true`, a new `create_*` boolean defaults to `false`, or a new `attach_*` boolean defaults to `true`, against [Feature Flag Naming and Default Polarity](../../terraform-module-maintainer/references/module-structure.md#feature-flag-naming-and-default-polarity).
- `structure.argument-order`: moved to [engine/check-c-structure.md](engine/check-c-structure.md#structureargument-order).
- `structure.multi-provider`: moved to [engine/check-c-structure.md](engine/check-c-structure.md#structuremulti-provider).
- A `validation` or `precondition` block added by the change has an `error_message` that names neither the accepted values or the bound nor the value that was received, against [Error Messages Name the Offending Value](../../terraform-module-maintainer/references/module-structure.md#error-messages-name-the-offending-value).
- An input the change adds or forwards is read only inside a branch another input switches off, so setting it does nothing and raises no error. The module's own creation flag `create` is not the switching input: every resource sits behind it and that is the intended shape. A feature flag named `create_<x>`, `attach_<x>`, `enable_<x>`, `manage_<x>` or `<x>_enabled` is not the switching input for an input whose name contains `<x>` as a run of whole `_`-separated tokens: `enable_log` exempts `log_group_name` and not `catalog_id`. For example `create_iam_role` for `iam_role_policies`, `create_policy` for `source_policy_documents`, `attach_policy` for `policy`, `enable_flow_log` for `flow_log_destination_arn`, `performance_insights_enabled` for `performance_insights_retention_period`, or `manage_default_security_group` for `default_security_group_ingress`: that input configures the thing the flag turns on. These are the family's feature flags, named in [Feature Flag Naming and Default Polarity](../../terraform-module-maintainer/references/module-structure.md#feature-flag-naming-and-default-polarity), plus two forms the family also uses: `<x>_enabled`, as `terraform-aws-rds` does for Performance Insights, and `manage_<x>`, as `terraform-aws-vpc` does for its default security group. Such a flag that switches off an input whose name does not contain `<x>` is the switching input. The rule is one input silently disabling another. An attribute a submodule's type discards on conversion is `structure.passthrough-field-drift`, and this rule is silent on it.
- `structure.passthrough-field-drift`, `structure.passthrough-default-drift`: moved to [engine/check-c-structure.md](engine/check-c-structure.md#structurepassthrough-field-drift) and [engine/check-c-structure.md](engine/check-c-structure.md#structurepassthrough-default-drift).
- A resource block the change adds omits a routing argument - `region`, `project`, `subscription_id` - that the resource's own schema carries, whose input exists, and which at least 80 percent of the other comparable resource blocks in that file set from a module input. `data` blocks do not count, a resource whose schema has no such argument is neither counted nor reported, and under 5 comparable blocks the rule stays silent. Run the count on the head under review; never recall it.
- A comment added by the change that directs a scanner to ignore, skip, or suppress a finding states no reason for accepting the risk, neither on the directive line nor on a comment line next to it, against [Scanner Suppressions](../../terraform-module-maintainer/references/module-structure.md#scanner-suppressions).
- Documentation the change adds or touches - a README section, a variable `description`, an example comment - describes behaviour no code path implements: an input it says is read, a value it says is reused, a mode it says is supported.
- An input whose accepted values are a closed set - a mode, an enum, a type name - has no `validation` block, or has one that is commented out, so a typo is accepted at the input and surfaces far from it, as a count of zero or an index error downstream.
- `structure.feature-above-version-floor`: moved to [engine/check-c-structure.md](engine/check-c-structure.md#structurefeature-above-version-floor).
- `structure.version-floor-understated`: moved to [engine/check-c-structure.md](engine/check-c-structure.md#structureversion-floor-understated).
- A comment the change adds restates what the code plainly says to a senior DevOps or SRE reader, against [Comments](../../terraform-module-maintainer/profiles/terraform-aws-modules/code-conventions.md#evidence-comments-copied-values-and-availability).
- A comment the change adds asserts a service limitation, a provider defect, an ordering requirement or other non-obvious behaviour with no link to an official source and no date, against [Evidence](../../terraform-module-maintainer/profiles/terraform-aws-modules/code-conventions.md#evidence-comments-copied-values-and-availability). Pre-existing comments, the `####` section-header banners and a scanner suppression are out of scope, and a suppression keeps `structure.suppression-unexplained`.
- A constant the change adds was copied out of a document - an IAM policy or SCP, an AWS account number, a literal ARN, a service principal, a condition key, a hosted zone ID - and carries no comment naming the source URL and the date, against [Copied values](../../terraform-module-maintainer/profiles/terraform-aws-modules/code-conventions.md#evidence-comments-copied-values-and-availability). A value the module computes, one from a `data` source, and a policy built from the module's own inputs are derived rather than copied. A value inside a comment, illustrating a format or a conversion, is not a constant the module uses and never fires this.
- A `validation` block the change adds depends on another variable or on how the module will be used, encodes a compliance or policy judgement, or re-implements a service-side naming or format rule, each as scoped by [Validation](../../terraform-module-maintainer/profiles/terraform-aws-modules/code-conventions.md#validation). `structure.validation-missing` is unaffected: a closed value set still needs its block.
- `structure.arn-partition-hardcoded`: moved to [engine/check-c-structure.md](engine/check-c-structure.md#structurearn-partition-hardcoded).

**Severity:**
- CRITICAL when a secure default is weakened: encryption, public access, logging, or deletion protection.
- HIGH when conditional creation is broken, an output will error instead of returning null, or a nested input does not match the schema shape. HIGH too when documentation promises behaviour no code path implements (`structure.docs-contradict-code`); an input the code reads nowhere is the other rule, `structure.input-ignored-in-branch`.
- HIGH when a new resource block omits a routing argument its siblings set (`structure.sibling-argument-omitted`), or an input ignored in a branch changes which resources are created, or grants or restricts access (`structure.input-ignored-in-branch`); CRITICAL when setting it destroys resources an existing caller already has, MEDIUM only when the effect is cosmetic.
- `structure.feature-above-version-floor`: moved to [engine/check-c-structure.md](engine/check-c-structure.md#structurefeature-above-version-floor).
- `structure.version-floor-understated`: moved to [engine/check-c-structure.md](engine/check-c-structure.md#structureversion-floor-understated).
- `structure.arn-partition-hardcoded`: moved to [engine/check-c-structure.md](engine/check-c-structure.md#structurearn-partition-hardcoded).
- `structure.passthrough-default-drift`: moved to [engine/check-c-structure.md](engine/check-c-structure.md#structurepassthrough-default-drift).
- `structure.passthrough-field-drift`: moved to [engine/check-c-structure.md](engine/check-c-structure.md#structurepassthrough-field-drift).
- MEDIUM when a must-pass structural convention is missed: missing `type`, missing `description`, wrong file, missing tag propagation, a scanner suppression with no reason for accepting the risk, a closed value set whose `validation` block is absent or commented out (`structure.validation-missing`; the wording of a message a present block does emit is `structure.validation-message-uninformative`).
- MEDIUM when a feature flag's prefix and its default disagree, or the module declares its own aliased provider configuration. Where a second provider configuration also changes what the caller has to pass in, Check A owns that part too.
- MEDIUM when a comment the change adds restates the code (`structure.comment-redundant`), or asserts a limitation, a defect or an ordering requirement with no source and no date (`structure.comment-unsourced`).
- MEDIUM when a copied constant carries no source URL and date (`structure.copied-content-unattributed`), or a `validation` block reaches past its own variable (`structure.validation-overreaching`).
- LOW when a should-pass convention is missed: grouping, section headers, argument order inside a touched resource block, naming consistency, an error message that tells the consumer neither the bound nor the value received.

`rule_id` prefix: `structure.`, for example `structure.create-flag-ignored`, `structure.output-no-try`, `structure.variable-untyped`, `structure.missing-description`, `structure.schema-shape-flattened`, `structure.sibling-block-asymmetry`, `structure.insecure-default`, `structure.wrong-file`, `structure.grouping`, `structure.flag-polarity`, `structure.argument-order`, `structure.multi-provider`, `structure.validation-message-uninformative`, `structure.suppression-unexplained`, `structure.input-ignored-in-branch`, `structure.sibling-argument-omitted`, `structure.docs-contradict-code`, `structure.validation-missing`, `structure.feature-above-version-floor`, `structure.version-floor-understated`, `structure.comment-redundant`, `structure.comment-unsourced`, `structure.copied-content-unattributed`, `structure.validation-overreaching`, `structure.arn-partition-hardcoded`, `structure.passthrough-field-drift`, `structure.passthrough-default-drift`.

## Suggested Fixes

Each row gives the fix a finding of that rule carries, in the forms of the [Suggested Fix Contract](findings-schema.md#suggested-fix-contract). `<...>` is what the finding fills in from its own evidence. A rule marked `needs decision` opens its fix with that prefix and lists the options; the maintainer skill applies none of them until a person chooses. A fix that adds, removes, renames or retypes an input or an output, or changes a default or a description, also names the generated content it makes stale, as the contract's Generated content item says.

| `rule_id` | Form | The fix |
|-----------|------|---------|
| `structure.create-flag-ignored` | code change | Gate the block on the module's creation flag the way its sibling blocks do, with the `count` or `for_each` expression they use, named. |
| `structure.output-no-try` | code change | Wrap the expression of `output "<name>"` in `try(<expression>, null)`, or change a fallback that changes the type to one of the output's own type, per [Conditional Outputs with try()](../../terraform-module-maintainer/references/module-structure.md#conditional-outputs-with-try). |
| `structure.variable-untyped` | code change | Add `type = <type>` to `variable "<name>"`, the type named from how the module reads it, per [Variable Types: Prefer Specific Over `any`](../../terraform-module-maintainer/references/module-structure.md#variable-types-prefer-specific-over-any). An `any` kept on purpose gets a comment with the reason instead. |
| `structure.missing-description` | code change | Add a `description` to the variable or output, with the text when the code determines it, per [Variable Descriptions](../../terraform-module-maintainer/references/module-structure.md#variable-descriptions). |
| `structure.schema-shape-flattened` | code change | Change the object type of `variable "<name>"` to nest as the provider's block does, with the nesting named, and the reads in the resource to match, per [Keep Nested Objects Matching Provider Schema](../../terraform-module-maintainer/references/module-structure.md#keep-nested-objects-matching-provider-schema). |
| `structure.sibling-block-asymmetry` | code change | Add to `dynamic "<name>"` the fields its siblings or the schema set and it lacks, each named, per [Consistent Field Coverage in Nested Dynamic Blocks](../../terraform-module-maintainer/references/module-structure.md#consistent-field-coverage-in-nested-dynamic-blocks). |
| `structure.insecure-default` | code change | Restore the secure default on `variable "<name>"`, the value named. |
| `structure.wrong-file` | code change | Move the named blocks from `<file>` to the archetype's file the directory already has, named. |
| `structure.grouping` | code change | Move the named variable or block into its group, per [Grouping](../../terraform-module-maintainer/references/module-structure.md#grouping) and [Section Headers](../../terraform-module-maintainer/references/module-structure.md#section-headers). |
| `structure.flag-polarity` | needs decision | Whether the feature is on by default: (a) set the default the prefix takes, named, and the guards that depend on the old default with it: a precondition, validation or example call that holds only while the flag is off fails once the default flips, so the option names each one and its change, such as a precondition that requires the input the flag consumes; (b) rename the flag to the prefix whose polarity matches its default, named, per [Feature Flag Naming and Default Polarity](../../terraform-module-maintainer/references/module-structure.md#feature-flag-naming-and-default-polarity). |
| `structure.argument-order` | code change | In the named block, move `count` or `for_each` to the first line and `tags` or `labels` to the last, per [Argument Order in a Resource Block](../../terraform-module-maintainer/references/module-structure.md#argument-order-in-a-resource-block). |
| `structure.multi-provider` | code change | Remove the aliased `provider` block, or the `provider =` or `providers =` argument, named. The caller passes a configured provider in instead, per [One Provider Configuration per Module](../../terraform-module-maintainer/references/service-archetypes.md#one-provider-configuration-per-module). |
| `structure.validation-message-uninformative` | code change | Rewrite the `error_message` to name the accepted values or the bound and to interpolate the value received, with the text given, per [Error Messages Name the Offending Value](../../terraform-module-maintainer/references/module-structure.md#error-messages-name-the-offending-value). |
| `structure.suppression-unexplained` | code change or needs decision | When the code shows why the risk is accepted, for example an input that controls it, add that reason on the directive line or the line next to it, per [Scanner Suppressions](../../terraform-module-maintainer/references/module-structure.md#scanner-suppressions). Otherwise `needs decision:` (a) keep the suppression with the author's reason; (b) remove it and fix what the scanner reports. |
| `structure.input-ignored-in-branch` | needs decision | Whether the input should work in that branch: (a) read it in the branch that ignores it, the change named; (b) reject it there with a `precondition` naming both inputs. |
| `structure.sibling-argument-omitted` | code change | Add `<argument> = <expression>` to the block, with the expression its siblings use. |
| `structure.docs-contradict-code` | needs decision | Which side is right: (a) change the documentation to what the code does, with the text given; (b) implement the behaviour it promises, the change named. |
| `structure.validation-missing` | code change | Add, or uncomment, a `validation` block on `variable "<name>"` that accepts exactly the listed values, with an `error_message` per [Error Messages Name the Offending Value](../../terraform-module-maintainer/references/module-structure.md#error-messages-name-the-offending-value). |
| `structure.feature-above-version-floor` | needs decision | Whether to raise the floor: (a) raise `required_version` to the introducing version, named, which is a `compat.version-constraint-raised` break for released callers; (b) replace the feature with one the floor has, named when one exists. For an OpenTofu-only feature in a module that admits Terraform, only (b). |
| `structure.version-floor-understated` | code change | Raise the caller's floor in its `versions.tf` to the callee's, named, and for disjoint sets remove the upper bound that excludes it, per [A caller does not declare less than what it calls](../../terraform-module-maintainer/profiles/terraform-aws-modules/code-conventions.md#a-caller-does-not-declare-less-than-what-it-calls). |
| `structure.comment-redundant` | code change | Remove the comment at the named line. |
| `structure.comment-unsourced` | code change | Add the official source URL and the date read to the comment at the named line. When no official source states the claim, remove the claim, per [Comments](../../terraform-module-maintainer/profiles/terraform-aws-modules/code-conventions.md#comments). |
| `structure.copied-content-unattributed` | code change | Add a comment above the constant with its source URL and the date read, the source named when the finding knows it, per [Copied values](../../terraform-module-maintainer/profiles/terraform-aws-modules/code-conventions.md#copied-values). |
| `structure.validation-overreaching` | code change | Remove the named `validation` block, or reduce its condition to the variable's own value, per [Validation](../../terraform-module-maintainer/profiles/terraform-aws-modules/code-conventions.md#validation). |
| `structure.arn-partition-hardcoded` | code change | Replace `arn:aws:` with `arn:${local.partition}:`, and a literal account or region with the module's local or input for it, adding the data sources and locals of the [Locals Pattern](../../terraform-module-maintainer/references/module-structure.md#locals-pattern) when they are absent, per [ARNs and partitions](../../terraform-module-maintainer/profiles/terraform-aws-modules/code-conventions.md#arns-and-partitions). |
| `structure.passthrough-field-drift` | code change | At the declaring line: add the attribute the root type lacks, with the submodule's type and default, or remove the attribute the submodule lacks. |
| `structure.passthrough-default-drift` | code change | At the declaring line, set the root side's unset value to the submodule's, named. |
